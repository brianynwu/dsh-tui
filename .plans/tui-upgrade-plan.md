# Plan: dsh-tui `0.1.8-revive` feature upgrade (6 features, gated rewind tail)

## Why

The operator cannot see or change the permission mode, cannot see the child agents couplers spawn, loses prompt history on every `/resume` re-exec, gets no desktop signal when a long turn waits for a user question, and reviews plans through a generic dialog. These are the gaps a user hits daily in herdr/mobile use. Rewind remains a desired sixth feature, but the current core forks a new agent/session at a completed-turn cut; it cannot continue our coupler-bound `main` in place. Features 1-5 ship on the existing pi-tui tree and dsh-core seams; nothing touches the couplers/overlay path or the in-place `/model` swap. Shell mode is deliberately OUT (the operator runs shell in a real terminal).

## Verified core baseline (not a phase)

The deployed Foundry `tools/orch/node_modules` tree has `@deepseek-ai/dsh-*` `0.1.5-rc.2`; the fork's development install omits some optional host packages, so it is not the authority for deployed service absence. The base profile composes three permission presets, subagent discovery, user questions, plan mode, session query, and persistence. Installed types and exports confirm the service names below. Runtime integration still needs the per-phase live checks; package source proves shape, not mounted behavior. Foundry now launches through `tools/orch/dsh.env.sh` (`dsh --profile tui`), not the retired `launch_dsh.sh`.

## Anti (shortcuts → closure by construction)

- **Shadow permission state** → the `${permission}` indicator reads the base's live/acknowledged mode on every render, never a fork-local variable set by the cycler. Test: mutate the fake seam externally, assert the fragment follows; an unknown/rejected/malformed mode is NEVER displayed as a guessed preset nor defaulted to broader access.
- **Silent escalation or stale model policy** → cycling into danger-full-access happens only on an explicit keypress while the composer owns focus. Invoke `/permission <name>` through the existing command path: a direct `permissionPresets.set()` changes enforcement but skips the live model policy notice. The indicator is in the default prompt template; malformed transitions cannot relax the floor.
- **Keymap dropping a safety key** → the validator parses EVERY binding against the probed pi-tui grammar (rejecting an unknown action or malformed syntax, not only a duplicate or an empty binding), and PROVES `exit`/`cancel`/each context's cancellation actually RESOLVE in every applicable context before accepting the map — so a nonempty typo cannot pass while leaving a safety action unreachable. An invalid replacement map is rejected ATOMICALLY (retain the last valid map; hot-reload never fails into a keyless or permissive-default UI). Reuse of one chord across mutually-exclusive contexts (picker vs composer) is valid.
- **Notification carrying untrusted text or claiming an unanswerable approval** → the OSC 9 payload is a FIXED literal, never the question/plan body/paths. Notify only for actionable TUI user questions. The deployed approval service has no TUI `approval/request` answerer, and that request payload has no stable ID; approval notification waits for a separate answerer design. Sanitize dynamic display text elsewhere.
- **History as a secret sink / lost update** → owner-only (0600) storage; concurrency-safe by construction (immutable, uniquely-named records published by atomic rename — NOT a single shared file with lost updates); validate record schema + filenames; ignore unfinished/truncated records; skip-not-fatal on corrupt lines; bounded (500 entries, 1 MiB aggregate, 64 KiB/entry — oversized prompts stay sendable, just unpersisted). Persist the ORIGINAL submitted text, not expanded fragments. Failures normalize to bounded notices (no raw prompts/paths/exception payloads) while in-memory history + sending stay functional.
- **Subagent view mutating main** → the child view is a read-only second transcript source; main's node identity, scroll state, editor contents, dashboard, and active dialogs are asserted unchanged across swap/back. Child replay triggers NO main-agent action, approval dialog, notification, or duplicate metric. Cancel stale subscriptions and reject late updates after a selection change. The composer, permissions, model selection, questions, and cancellation stay attached to main.
- **Plan panel authorizing an action** → rendered content cannot authorize; expose EXACTLY the response actions/values the core payload supports (never invent approve/revise semantics or infer a plan from its title); preserve FIFO overlay ordering, pending state, single-response behavior; fall back to the generic dialog when the plan discriminator is absent.
- **Fake rewind (future-cycle constraint)** → a later rewind design must continue the coupler-bound canonical `main`, never clear/hide rendered rows. The current core fork produces a new agent/session and cannot meet this condition. Keep rewind UI and its key action out of Phases 1–5.
- **Classify every knob (no floor relaxes)** → core permission presets select ENFORCED policy; keymaps select INVOCATION not authorization; display/notification preferences alter PRESENTATION only; persistence/output ceilings BOUND RESOURCES and cannot disable validation; all feature state is runtime state — no env flag relaxes an enforcement or integrity floor.

If the same finding class recurs, stop rewording cases — close the surface by construction or narrow the claim.

## Bounds

In this cycle: Phases 1–5 and the recorded Phase 6a source probe. Phase 6b is a separate cycle contingent on a core seam or explicit rebinding design that preserves the composed `main` behavior. Out: the completed dsh-core update, **shell mode (dropped)**, competitor code, all Tier C, changes to coupler wiring, behavior env flags, and a TUI approval answerer. Each implemented phase is one branch, one `lib/` rebuild, one prerelease bump (`0.1.8-revive.N`), its own tests + a live-verify note in the PR body. No new third-party runtime package is needed; imports of deployed core services require matching core peer/dev declarations in the fork. `node:fs`/`node:path` cover the history store. A future rewind changes conversation history only; it cannot undo filesystem changes, commands, or external effects (state this in its picker).

## Trade

- **Structural foundation first (operator choice).** Combining the keymap with the toggle front-loads the key-dispatch→action-dispatch migration into Phase 1 (bigger, higher blast radius) and settles Shift+Tab ownership before any later phase adds a chord. Cost: the first phase is M; phases 2–5 add actions through the dispatch rather than raw key branches.
- **Additive beats tidy.** The subagent view duplicates a transcript instance behind a source swap rather than refactoring the main render path. Cost: two render paths; benefit: zero change to the live main path, delete-the-file removal.
- **Rewind gating:** the checked seam does not continue `main` in place. Design the rebinding or obtain a new core seam in a separate cycle before implementing rewind.
- New controllers sit behind existing services + small composition-root registrations; the shared renderer/editor/event-reducer must not import feature controllers (removal = drop registrations + feature files, base intact). Use existing persistence/rendering/validation where adequate, else Node stdlib — no plugin framework, no storage dependency.

## Verified seams and remaining probes

- **Permission:** `ctx.permissionPresets.names`, `.current(session)`, and `.set(session,name)` exist. The configured base profile composes read-only, workspace-write, and danger-full-access. A direct `.set()` updates policy but does not inject the live model notice; `/permission <name>` does. `current()` can report `custom`, which is displayable but never a cycle target. The fork already has a `runCommand()` path for core commands.
- **Questions and approvals:** the question queue holds `PendingQuestion` objects. An item `id` is caller supplied and may recur across requests (plan mode uses `plan-review`). A TUI question can be deduped by pending object identity for its current lifetime. On teardown, that pending request rejects; a later mount receives a new request. The approval audit event has an ID, but `approval/request` omits it and the TUI has no approval answerer. The deployed default policy is danger-full-access/never; changing to an ask policy does not create an answerer.
- **History:** `dshHomePath()` honors `DSH_HOME`; Foundry's `dsh.env.sh` exports it and `/resume` carries `process.env` through execve. The vendored editor has `addToHistory()` with a 100-item cap and calls `navigateHistory()` from its input handler. The 500-record goal needs a narrow editor adapter or hook for refresh before navigation and a larger in-memory cap, while storage remains TUI-owned.
- **Subagents:** `ctx.subagents.listChildren(parentSessionId,signal)` returns `child` rows (`id`, `mode`, optional `label`, `activity`, `hasChildren`) or `diagnostic` rows (`reason`). `activity=running` means resident, not actively executing; derive active execution from `ctx.agents.get(id)?.status`. `ctx.sessionQuery.observeSession(id)` supplies an immutable event snapshot and cursor; `session/event` supplies live events. Subscribe and buffer first, then snapshot and dedupe by sequence. `ctx.agents.isOwnedBy` checks live ownership; durable lineage is distinct.
- **Plans:** `intent.kind === 'plan-review'`, `intent.approve`, and `detail` are real question fields emitted by core plan mode. Render `detail`, return exact advertised answer labels, and use the generic dialog for other intents.
- **Rewind:** `Session.snapshotEvents` and `SessionStore.fork` exist, but the installed session controller continues a fork as a new agent/session. `AgentRegistry` has no replace/adopt seam. This fails the in-place `main` gate now, so Phase 6b is deferred.
- **Per-phase probes still required:** pi-tui key-event grammar and Shift+Tab focus ownership; raw terminal OSC delivery (the terminal has `.write`); editor navigation adapter behavior and store failure cases; replay/live event ordering and cleanup under actual child streams; plan modal interaction under real question requests; mounted services and package declarations. The fork's module and `cordis.patch.yml` TUI injection declarations need the permission/subagent services when consumed. Add matching core peer/dev dependencies for newly imported packages, including `dsh-home-paths` if used.
